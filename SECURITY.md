# Security Policy

## Responsible Use Statement

HexHound is a **security awareness and education tool**. It is designed to help people learn about wireless network security, Bluetooth tracking risks, and the importance of physical device security through an engaging, gamified experience.

## What HexHound Is Designed For

- Security awareness training in corporate and educational settings
- Penetration testing demonstrations with proper authorization
- Personal security auditing of your own networks and devices
- Learning about Wi-Fi, BLE, and USB HID security concepts
- Having fun with a cybersecurity-themed digital pet

## What HexHound Is NOT Designed For

- Unauthorized network scanning or reconnaissance
- Attacking, disrupting, or interfering with networks you do not own
- Unauthorized USB HID injection on machines you do not control
- Bypassing security controls or gaining unauthorized access
- Any activity that violates applicable laws or regulations

## USB HID Missions

HexHound includes USB HID keyboard emulation missions. These missions type text to a connected computer's keyboard input.

**This functionality is for educational use only, on hardware you own or have explicit written authorization to test.**

Unauthorized use of HID injection on systems you do not control may violate:
- The Computer Fraud and Abuse Act (CFAA) in the United States
- The Computer Misuse Act (CMA) in the United Kingdom
- Similar computer crime legislation in other jurisdictions

The authors assume no liability for misuse.

## Reporting Security Vulnerabilities

If you discover a security vulnerability in the HexHound firmware, please report it responsibly:

**Report privately:** open a GitHub security advisory on the repository.

Please include:
- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if any)

This is a hobby project maintained in spare time, so the honest commitment is
a modest one: expect an acknowledgement within a week, and a timeline for a fix
once the report has been reproduced. A 48 hour promise would be a nicer
sentence and a worse commitment, because nobody is on call for this.

If a report is credible and unfixed, it will be said so publicly rather than
left quiet. Nothing here is a warranty; see the licence.

**Do not** open a public GitHub Issue for security vulnerabilities.
